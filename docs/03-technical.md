# 技術計画書

企画書（`docs/01-overview.md`）のうち、技術に関わるものをまとめる。
2章の技術スタックはチームで合意済み。

## 1 決まっていること
- LLM の出力は JSON で構造化する（問い・式・変数・単位・正解・解説・出典）。条件変更のスライダーは、この式と変数を使ってアプリ側で再計算する
- LLM に送る画像は囲んだ範囲の切り抜きだけにする（全体の画像は送らない）
- 応答待ちを短くするため、囲んだ直後に LLM の呼び出しを始め、認識結果の確認中も裏で問いを作る（先読み生成）
- 通信はオンライン必須（通信できないときはエラーを表示する）
- アーカイブはクラウド（Firestore）に保存する（写真は切り抜きのみ。画像も Firestore に入れ、Storage は使わない）
- 認証は自作せず Firebase Authentication を使う（パスワードリセットはなし。理由は2.1）
- API の利用回数はハッカソン期間中は制限しない
- MVP ではテストを書かない（フェーズ 3-0 で入れる）

## 2 技術スタック
| 項目 | 決定 | 理由 |
|---|---|---|
| プラットフォーム | Web アプリ（PWA） | URL を開くだけでスマホ実機で動き、ストアへの提出が要らない |
| フロントエンド | Next.js（React + TypeScript） | 画面とサーバー側の処理（LLM の呼び出し）を1つのリポジトリで書ける |
| CSS | Tailwind CSS | スマホ幅への対応が書きやすく、分担しても書き方がそろいやすい。色・影・角丸は `docs/design/tailwind-theme.css` と同じ値を `src/app/globals.css` の `@theme` に置く。フォント（Mochiy Pop One・Zen Maru Gothic）は `next/font/google` で読み込む |
| パッケージ管理 | npm | 全員が追加のインストールなしで使える |
| DB | Firebase（Firestore） | 導入が速く、セキュリティルールで「本人だけ」を制御できる |
| 画像の保存先 | Firebase（Firestore に直接保存） | Storage は従量課金の Blaze プラン（クレジットカード登録）が必須のため。切り抜き画像は数百KBで、1件 1MiB の上限に収まる |
| 認証 | Firebase Authentication | 認証を自作しない。Firestore のルールと連携できる |
| ホスティング | Vercel | Next.js をそのまま公開できる。HTTPS なので、スマホでカメラを試せる（公開のしかたは 10章） |
| LLM | Claude（既定は Opus 5.5 `claude-opus-5-5`。本番は Sonnet 5.5 `claude-sonnet-5-5`・effort low） | 画像入力と JSON の構造化出力に対応。本番は、待ち時間と費用のバランスで Sonnet にしている（9章の実測） |
| 式の計算 | math.js | LLM が出した式を、eval を使わずに安全に計算できる。単位の変換もできる |
| JSON の検証 | Zod | JSON の形を1か所で定義し、型と検証の両方に使える |

- 使うパッケージ（予定）：`next` `react` `tailwindcss` `firebase` `@anthropic-ai/sdk` `mathjs` `zod`。追加するときは AGENTS.md の禁止事項3に従って確認する

### 2.1 認証の方式
- ログイン ID はユーザー名。内部で `<ユーザー名>@<FirebaseのプロジェクトID>.firebaseapp.com` に変換して、Firebase Authentication のメール／パスワード方式で登録する（アプリからメールは送らない）
- ユーザー名にはひらがなも使えるようにする。メールアドレスに使えない文字があるため、ユーザー名を英数字に変換（例：UTF-8 のバイト列を16進数にする）してからメール形式にする
- 変換するとひらがな1文字が6文字になる。メールアドレスの `@` より前は64文字までなので、ユーザー名の長さの上限：【未決】（16進数なら10文字程度）
- メールアドレスを集めないため、パスワードリセットはできない（パスワードを忘れるとアーカイブに戻れない）
- 1つのアカウントの中に複数のプロフィール（子どもごと）を持つ
- 学校版（未実装）：Google・Microsoft のログインと、学校のメールアドレスとパスワードの方式を足す。いまの方式も残す（`docs/06-school-expansion.md` 3章・10.1）

### 2.2 LLM の呼び出し
- Next.js の Route Handler（サーバー側）から公式 SDK（`@anthropic-ai/sdk`）で呼ぶ。`ANTHROPIC_API_KEY` はサーバー側の環境変数だけに置く
- API はログインした人だけが呼べるようにする。画面から Firebase の ID トークンを送り、サーバー側で、Google の公開鍵を使って署名・期限・発行元・対象を検証する（`src/server/auth.ts`。`firebase-admin` は本番の Vercel で読み込みエラーになったため使わない）（URL を知っている人に使われて課金が膨らむのを防ぐ）
- 出力は構造化出力（`output_config.format`）で JSON の形を指定し、受け取った後に Zod でも検証する
- 断られたとき（`stop_reason: "refusal"`）は別のモデルに切り替えず（`fallbacks` は使わない）、「別のものを囲んでみてね」と表示する。`content` を読む前に必ず `stop_reason` を確認する
- effort（考える深さ）の既定は medium。環境変数 `LLM_EFFORT` で変える（本番は low）。待ち時間はナビゲーターキャラの豆知識（まめちしき）でつなぐ
- 料金と時間の目安：9章の実測（モデルと設定で、1回あたり約 0.3セント〜12セント、3秒〜45秒）

### 2.3 Vercel の制限（Hobby プラン）
- 関数の実行時間：最大 300 秒。60 秒で打ち切る（5.4）ので収まる。ストリーミングは使わない
- リクエスト・レスポンスの大きさ：4.5 MB まで。画像を長辺 1024px に縮小する（5.1）ので収まる
- 関数が動く地域：初期設定はアメリカ（`iad1`）なので、東京（`hnd1`）にしている（`vercel.json`）
- Node.js：22.12 以上（`package.json` の `engines`）。Vercel のプロジェクト設定は 24.x

## 3 全体構成
```
[スマホのブラウザ（Next.js の画面）]
   │  撮影・囲む・切り抜き・縮小・予想・可視化・math.js で再計算
   │
   ├─ Firebase Authentication ……… ログイン（ID トークンを受け取る）
   ├─ Firestore ………………………… プロフィール・アーカイブ・切り抜き画像を読み書き（ルールで本人だけ。グループの投稿はメンバーだけ）
   │
   └─ Next.js の Route Handler（Vercel・東京）
         │  ID トークンを検証（Google の公開鍵）
         └─ Claude API（API キーはここだけ）
```
- クライアント：撮影、囲む操作と切り抜き、予想の入力、可視化、再計算、アーカイブの表示。Firebase に直接読み書きする
- サーバー：LLM の呼び出しだけ。DB には書かない（保存は画面から行う）
- 学校版（未実装）では、招待コードの確認・自動チェック・通報のために、サーバーの役割を見直す可能性がある（`docs/06-school-expansion.md` 10.3）

## 4 処理の流れ
```
撮影 → 囲む → 切り抜き・縮小（EXIF も消える）
  → /api/questions に「画像 + 学年 + 出題済みの組み合わせ」を送る（ここから裏で生成）
  → 「これは○○だね？」の確認（違えば修正して作り直す）
  → 問い 3 つ（JSON）→ 検証・math.js で正解を計算 → 選ぶ → 予想
  → 答え合わせ・可視化 → スライダーで再計算 → アーカイブ保存（Firestore）
```
- 自分で問いを書いた場合は、`/api/questions/custom` に「画像 + 学年 + 問いの文」を送り、同じ形の問いを 1 つ受け取る
- 認識結果を修正したときは、修正した名前を付けてもう一度呼ぶ（ユーザーの操作で呼ぶ1回であり、自動リトライではない）

## 5 LLM
### 5.1 入力
- 画像：囲んだ範囲の切り抜きだけ。ブラウザの Canvas で長辺 1024px の JPEG に描き直す（このとき EXIF も消える）。保存用（Firestore）にも同じ画像を使う
- 学年（大まかな目安）
- 学習の進み具合（問いを高度にするため。測り方は `docs/02-spec.md` 17章：自分で作った問い1つで1点・「ピタリ」「おしい」で もう1点、5点ごとにレベルが1つ上がる）
- 出題済みの「対象×分野（単元）」の組み合わせ（そのプロフィールのアーカイブから取り出す）
- （修正時）ユーザーが直した認識結果／（自分で書く方式）問いの文

### 5.2 出力（JSON）
| 項目 | 内容 | 型・形式 |
|---|---|---|
| 認識結果 | 「これは○○だね？」に使う名前と、問いが作れるか | `recognition: { label: string, canAsk: boolean }` |
| 問い | 問題文（学年に合わせた漢字・ふりがな） | `questions[].text: string`（ふりがなは `{漢字\|よみ}` の短い記法で書かせる。熟語はことば全体に1つ付ける（`{前提\|ぜんてい}` ○／`{前\|まえ}{提\|てい}` ✕）。文はわかち書き。表示前に、22px 以上は `<ruby>` に、それより小さいときは読みに置きかえる（`src/lib/ruby.ts`）。それ以外のタグはすべて文字として表示する。古い `<ruby>` タグの保存データも読める） |
| 問いのタイプ | 数量推定・比較・「なぜ？」型 | `questions[].type: "estimate" \| "compare" \| "why"` |
| 分類 | 算数・理科・情報／単元／対象 | `subject: "math" \| "science" \| "info"`、`topic: string`、`target: string` |
| 式 | math.js で計算できる式。「なぜ？」型は null | `formula: string \| null`（例：`"length * width / tileArea"`） |
| 変数 | 名前・表示名・値・単位・スライダーの範囲 | `variables: { name, label, value, unit, min, max, step }[]` |
| 単位 | 答えの単位（学年で習ったもの） | `answerUnit: string` |
| 正解 | LLM が考えた値（確認用。表示には使わない） | `llmAnswer: number \| null` |
| 選択肢 | 「なぜ？」型の選択肢（理由・結果・どっち。2〜3つ。正解の印つき） | `choices: { text, correct }[] \| null` |
| ねらい・入れかえ判定 | 内部で使うだけ（表示・保存しない）。ねらった「そのもののふしぎ」と、ものの名前を入れかえても成り立つか | `secret: string`、`swappable: boolean` |
| 解説 | まず一言と、タップで見る計算過程のステップ | `explanation: { short: string, steps: string[] }` |
| 出典 | 根拠データ・前提条件 | `sources: { title: string, url: string \| null, assumption: string }[]` |
| ヒント | 問いの見かた・前提（答えのヒントではない） | `hint: string` |
| 身近なおきかえ | 答えを身近なものにおきかえる（`per`：答え÷value を「unit ぶん」、`times`：答え×value） | `ref: { type: "per" \| "times", label, value, unit } \| null` |
| 条件のといかけ | 条件を変えたくなる一言 | `whatIf: string` |
| 関連・しらべことば | 同じ考えかたの別の問い（0〜2）・もっと調べるときのことば | `related: string[]`、`keyword: string` |

- 1回に出す問いの数：問い生成は 3 つ（3択方式のため）、自分で書いた問いは 1 つ
- 比較型の式と答えの持ち方：【未決】（予想の入力方法は 02-spec 10章で決定済み：4年生までは2択＋何倍かの選択肢、5年生以上は何倍かをスライダー）
- 正解の担保の仕方：
  - 表示する正解は、math.js で式と変数から計算した値を使う（LLM の値は使わない）
  - LLM の値（`llmAnswer`）と計算値が大きくずれる問いは、式が間違っているとみなして出さない（ずれの許容範囲：5%以内）
  - 3 つとも出せないときはエラー表示にする

### 5.3 プロンプト
- いちばん大事なのは、囲んだ「そのもの自身」への「なんで？」（正解を当てさせるテストにしない）。問いは、そのもののふしぎ・しくみ・ひみつにする
  - 問題文は、みじかい1〜2文。細かい条件や専門の数・ことば（「1びょうに44100かい」など）をならべない。数字は必ず出さなくてよく、直感で答えられる「なぜ？」型を中心にしてよい
  - そのものと関係のないもの（ゾウ・ビル・月 など）との大きさくらべにこじつけた問い、ものの名前を入れかえても成り立つ問いは作らせない
  - 3つのうち「なぜ？」型を1つ以上、数で答える問いは1つ入れ、あわせて2つまで。subject（算数・理科・情報）はなるべくばらばらにする
  - 算数（math）の問いは、どのものにも言える かけ算（「1日2時間つかうと1年で何日」など）にしない。そのものがかくしている、かたち・ならび・くりかえし・つくりの数（ならべかたの数、部分と全体の大きさ、ふえかた、確率・平均）を選ばせる
  - 数で答える問いでは、意外性（予想が数倍ずれる、思いこみがひっくり返る）を使う。「数えるだけ」「1回のかけ算で出る」「答えが問題文に書いてある」問いは作らせない
  - 仕組み：出力の形に、ねらい（`secret`）と入れかえ判定（`swappable`）を、問題文より先に書かせる。`swappable` が true の問い、問題文が140字をこえる問い、数が3つ以上（1をのぞく）または10000以上の数が入った問いは、出さない（`src/server/llm/validate.ts`。自分で書いた問いと見本の問いは対象外）。`secret`・`swappable` は保存しない
- 直感が外れやすい問いの例を与える
- 確率・場合の数の式用に、`harmonic(n)`・`fact(n)`・`comb(n,k)`・`birthday(n)` を使えるようにしてある（`src/lib/calc.ts`）
- 学年に合わせた問い・漢字・単位にする
- むずかしいことば（前提・仮定・根拠 など）を使わず、やさしいことばに言いかえさせる（言いかえの表は `docs/02-spec.md` 2.2）。出力の形の説明（`schema.ts` の describe）にも、むずかしいことばを書かない（AI がそのまま使うため）
- 出題済みの組み合わせと同じ問いを出さない
- 子ども向けとして不適切・危険な内容（火・刃物・電気・薬品・高い所・道路など）を出さないよう制約する
- 計算は LLM にさせず、式と変数を出させる
- 置き場所：LLM まわりは `src/server/llm/` にまとめ、画面側から import できないようにする（`server-only`）
```
src/
  app/api/questions/route.ts         … 問い生成
  app/api/questions/custom/route.ts  … 自分で書いた問い
  server/llm/prompts.ts              … プロンプト（ここだけに書く）
  server/llm/schema.ts               … JSON の形（Zod。検証と型に使う）
  server/llm/client.ts               … Claude の呼び出し
```
- アプリ全体のディレクトリ構成は AGENTS.md を参照

### 5.4 エラー処理
- 形式の崩れ・タイムアウト・API エラー・断られたとき・ID トークンが無効なときに、子どもにも分かるメッセージとやり直すボタンを出す
- タイムアウト：60 秒（囲んでから問いが出るまでの目標も60秒以内。待ち時間はナビゲーターキャラの豆知識でつなぐ）
- 断られたとき（refusal）：別のモデルには切り替えず、「別のものを囲んでみてね」と表示する
- 自動リトライはしない（課金とレート制限のため。SDK の自動リトライも 0 にする）
- 見本の絵（ガチャ・信号・氷のコップ）を使っているときだけ、AI が使えなければ、AI を呼ばずに見本の問い（`src/server/llm/builtin.ts`）に切り替える（ユーザーの操作ではなく、エラー時に1回だけ。画面に「みほんの もんだい」と表示する）
- ログに画像・トークン・API キーを出さない

## 6 データ
| データ | 主な項目 | 保存先 |
|---|---|---|
| アカウント | ユーザー名（メール形式に変換したもの）・パスワード | Firebase Authentication（パスワードはアプリで扱わない） |
| プロフィール | ニックネーム・学年・あそびかたの説明を見おわった時刻 | Firestore |
| アーカイブ | 問い・式・変数・予想・結果・解説・出典・分類 | Firestore |
| 切り抜き画像 | JPEG（base64） | Firestore（アーカイブと同じドキュメント） |
| 出題済み | 対象×分野（単元） | アーカイブから取り出す（別に保存しない） |
| 収集要素 | スタンプ・称号 | アーカイブから数える（別に保存しない）。称号は20種類 × どう・ぎん・きん（`src/lib/titles.ts`・`docs/02-spec.md` 16章）。使っている称号は、プロフィールの `title`（「math-gold」などの ID） |
| グループの投稿 | 切り抜き画像・問い・称号 | Firestore（`groups/{groupId}/posts`。位置情報・ユーザー名・ニックネームは入れない） |

- 構成（いまの実装。型は `src/lib/types.ts`）：
```
Firestore:
  users/{uid}
    └ profiles/{profileId}          id, nickname, grade, title（使っている称号の分類 or null）,
         │                          firstMode（"choices" | "custom"）, guideSeenAt, createdAt
         └ archives/{archiveId}     id, createdAt, grade, question（5.2 の問い 1 つ分）,
                                    guess（予想）, rating（"pita" | "oshii" | "ohazure"）,
                                    image（切り抜きの data URL）, sharedGroups（見せているグループの ID）
  groups/{groupId}                  autoJoinUntil（自分で入れる期限。jphacks だけ）, joinCode（いまの参加コード。#137）。コンソールで作る
    ├ missions/{日付}               date（日本時間の「2026-11-15」）, text（ひらがな・60文字まで）, updatedAt（#139）
    ├ members/{uid}                 role（"member" | "admin"）, joinedAt, username（ログイン ID。#129 より前の記録にはない）,
    │                               joinCode（参加コードで入ったときの、そのコード）
    ├ posts/{postId}                id, createdAt, image, text, subject, topic, title
    │                               （ユーザー名・ニックネーム・位置情報・持ち主は入れない。ID はアーカイブと同じ）
    └ owners/{postId}               uid（投稿の持ち主。だれも読めない。本人が消せるようにするためだけに持つ）
```
- 開発用のローカル版（`NEXT_PUBLIC_BACKEND=local`）は、同じ形をブラウザの localStorage に保存する（`src/lib/backend/local.ts`）
- あそびかたの説明を見おわったか（`docs/02-spec.md` 4.2）は、プロフィールの `guideSeenAt` に持つ（2026-11-06 に決めた）
  - 値：見おわった（とばした）時刻（ミリ秒）。はじめての登録でプロフィールを作るときは `null`（まだ見ていない）にする
  - `guideSeenAt` が `null` のときだけ、ホームで説明を出す。項目がないプロフィール（この機能より前に作ったもの・`/demo` の見本のプロフィール）は、見おわったとして扱い、出さない
  - 「とばす」「とじる」「ホームを みる」「やってみる！」「とばして はじめる」の どれでも、いまの時刻を入れる（`AuthProvider` の `markGuideSeen`）。保存に失敗しても説明は閉じる（次に ホームを開いたときに また出る）
  - プロフィールに持つので、いまの `firestore.rules` のまま本人だけが読み書きでき、ローカル版も同じ形で保存される。いまは1アカウントに1プロフィールなので、アカウントごとに一度だけ出る（`docs/06-school-expansion.md` 4.2）。プロフィールの切り替え（MVP 以降）を作ったときは、子どもごとに一度だけ出ることになる
- 画像の大きさ：Firestore の1件は 1MiB まで。base64 にすると元の約1.33倍になるので、JPEG の品質を調整して 1件が 1MiB 未満に収まるようにする
- アクセス制御：Firestore のセキュリティルール（`firestore.rules`）で、`users/{uid}` の下は uid が自分のときだけ読み書きできるようにする。グループの分は下の「グループ」のとおり。ルールに書いていないもの（やめた `public`・`publicOwners` など）は、だれも読み書きできない
- 全員への匿名公開（`public`・`publicOwners`・「みんなにも みせる」）は、グループの共有（#120）に置きかえて、やめた（2026-11-06 に決めた）。コードとルールから消した。前の投稿は #82 で消してある。古いアーカイブに `publicId` が残っていることがあるが、使わない
- グループ（「みんなの はてな」で はてなを見せあう。#120。2026-11-06 に決めた）
  - グループは3つ：`jphacks`（JPHACKS。発表の日に参加者が見せあう）・`csennkai`（C専会。チームメンバーの確認用）・`c3`（C3。手で入れる。2026-11-06 に足した）。画面に出す名前と、自動で入るかは `src/lib/constants.ts` の `GROUPS`
  - グループの文書（`groups/{groupId}`）・管理者・C専会のメンバーは、人が Firebase のコンソールで作る（アプリからは作れない。作る・変えるのは人間の許可を取ってから）
  - 入り方：新しく登録した人は、はじめての登録（`/profile` の「じゅんび できたよ」の前）で JPHACKS に自動で入る（`AuthProvider` の `saveProfile` → `joinAutoGroups`）。入れなくても登録は止めない。ルールで、`groups/jphacks` の `autoJoinUntil`（タイムスタンプ）より前で、`role` が `member` のときだけ自分で作れる。`autoJoinUntil` がない・過ぎたグループには入れない（C専会・C3 には `autoJoinUntil` を入れない）
  - チームメンバーは両方に入る。C専会・C3 と、登録より前のアカウントの JPHACKS は、コンソールで `members/{uid}` を作る（`role`：`member`、`joinedAt`：その日時、`username`：ログイン ID）
  - メンバーの記録の `username`（ログイン ID。#129）：管理画面のメンバーの一覧に出すため。読めるのは本人と管理者だけ。自分で入るときは、ルールで ID トークンの名前（`request.auth.token.name`。登録のときにログイン ID を入れている）と同じかを確かめる（ほかの人の名前を名乗れない）。登録した直後のトークンには名前がないことがあるので、トークンを取り直してから書き、それでも断られたら `username` なしで1回だけ入りなおす（`joinAutoGroups`）。`username` がない記録は、一覧に uid の頭を出す
  - 管理者：`members/{uid}` の `role` を `admin` にする（コンソールから。または、管理画面で ほかの管理者が「管理者にする」）。管理者は 2026-11-06 に決めた：ログイン ID `saku_0875`（3つのグループすべて）
  - 読めるのはグループのメンバーだけ・作れるのはメンバーの本人だけ・消せるのは持ち主とグループの管理者（ルールで確かめる。画面で隠すだけにしない）。投稿の形は `validPost`（項目の種類・型・文字数（問題文 400 文字、題材 100 文字まで）・画像（切り抜きの JPEG で 650,000 文字まで））で確かめる。書きかえはできない
  - 投稿の持ち主：同じ人の投稿をひも付けられないよう、投稿には持ち主・ニックネーム・ユーザー名を入れない。持ち主の uid は `groups/{groupId}/owners/{postId}` に分け、だれも読めない（本人も管理者も読まない）。投稿と同じバッチで書く・消す（`src/lib/backend/firebase.ts` の `saveGroupPost`・`deleteGroupPost`）。持ち主の記録は、まだない投稿を同じバッチで作るときだけ作れ、投稿を残したまま消せない。もうない投稿を消す操作は通す（管理者が消したあとも、ずかんの「けす」「なかまに みせるのを やめる」が失敗しないように）
  - 通報：`groups/{groupId}/reports/{投稿のID}__{通報した人のuid}`（項目は `postId`・`createdAt`（サーバーの時刻）だけ）。作れるのはメンバーで、投稿があるときだけ。同じ人の2回目は ID が同じなので作れない（アプリは成功として扱う）。読める・消せるのは管理者だけ（`firestore.rules`）。管理画面（`/teacher/groups`）は、通報の数を出して、通報された投稿を先頭にする。投稿は自動では隠さない（乱用で消されないようにするため）
  - アーカイブの `sharedGroups` に、見せているグループを持つ（投稿の ID はアーカイブの ID と同じ）。「きみの はてな」の印は、これと照らして出す。ずかんを読み込んだとき、投稿がもうないもの（管理者が消したなど）は `sharedGroups` から外して保存する（`ArchiveProvider` の `clearGoneShares`）。確かめるのに失敗しても、ずかんはそのまま見せる
  - 管理画面（#120・#129）：見本（デモ）ではなく本番のデータを扱う。子どもの画面と同じアカウントでログインして使う。子どもの画面には入口を出さない
    - 入口：`/teacher` のクラスの切り替えの下の段「グループ（本番のデータ）」（ログインしていて、管理者になっているグループだけ出る）か、`/teacher/groups`（管理者になっている はじめのグループの「きょう」へ移る）
    - `/teacher/groups/{グループ}`（きょう。`GroupTodayScreen.tsx`。#140）：きょう（日本時間の0時から）の投稿の数（`countGroupPostsSince`。サーバーで数えるので画像を読まない）、通報された投稿の数、メンバーの数と きょう入った人の数、きょうのミッション、参加コードと自動で入るかのようす、新しい投稿6件。子どもどうしを比べる数（人ごとの件数・当たり外れの割合）は出さない。1つが読めなくても、ほかは出す
    - `/teacher/groups/{グループ}/hatena`（はてな。`src/components/teacher/GroupsScreen.tsx`。#138）：投稿を新しい順に30件ずつ読み（「もっと見る」で前の30件を足す。`listGroupPosts` の `before`）、分野・単元（投稿の topic）で しぼって、見て消せる。通報された投稿は、まだ読んでいない古いものも1件ずつ読みにいって先頭に出す。だれの投稿かは出ない。授業中の記録（予想と結果）は出さない（子どものずかんを管理者が読めるようにする変更になるため）
    - `/teacher/groups/{グループ}/members`（メンバー。`GroupMembersScreen.tsx`）：一覧（ログイン ID・役割・入った日時。ニックネームは出さない）、ログイン ID でさがす、管理者にする・メンバーにもどす、グループから外す（その人が見せた投稿は残る）、自動で入るのを止める（`autoJoin` のグループだけ）
    - ルール：役割を変える・外すのは管理者だけで、自分の役割は変えられず、自分は外せない（管理者がいなくなるのを防ぐ）。役割は `member`・`admin` だけ、変えられるのは `role` だけ。自動で入る期限は、管理者が、まだ入れるあいだに「いま」にする（止める）ことだけができる。延ばす・入れなおすのはコンソールから
    - メンバーを入れるのは、参加コード（#137。下）か、コンソールから
  - ミッション（#139。2026-11-06 に決めた）：`groups/{グループ}/missions/{日付}`。読めるのはメンバー、書く・消すのは管理者
    - 日付は日本時間（`src/lib/missions.ts` の `jstDate`。グループのメンバーは日本で使う前提）。ルールで、日付の形・ID と `date` が同じ・文が 1〜60 文字・漢字がない（`\p{Han}`）を確かめる
    - 管理画面：`/teacher/groups/{グループ}/missions`（`GroupMissionsScreen.tsx`）。これから15日（きょうを含む）とこれまで7日を ならべ、これからの日に出す・変える・消す。漢字があれば保存させない
    - 子どもの画面：ホームとお題の画面で、入っているグループの きょうの分を読み（`useTodayGroupMissions`）、あれば グループの名前つきで ぜんぶ ならべる。読み込み中・どこも出していない・読めなかったときは、いつもの毎日のお題
  - 参加コード（#137。2026-11-06 に決めた）：サーバーは使わず、ルールで確かめる
    - `joinCodes/{コード}`：`groupId`・`open`（受付中か）・`createdAt`。コードは 8 文字（見まちがえやすい 0・O・1・I・L を使わない英大文字と数字。`src/lib/joinCode.ts`）。暗号用の乱数で作る。ログインした人は1件ずつ読めるが、一覧はだれも読めない（総当たりで当てられないように）
    - 管理者は、メンバーの画面（`JoinCodePanel.tsx`）で、コードを作る・作り直す・受付を止める・再開する。作るときは、新しいコード・グループの `joinCode`・前のコードを消す、を同じバッチで書く（ルールで、グループの いまのコードは消せない・ほかのグループのコードを自分のグループのものにできない）
    - 子どもは「せってい」→「グループに はいる」（`/join`）か、どこにも入っていないときの「みんなの はてな」からコードを入れる。小文字・全角・空白・ハイフンはそろえる。入るのは `member` だけ（ルールで、受付中の このグループのコードを入れたときだけ作れる。`joinCodeOk`）。ログイン ID は自動で入るときと同じく、ID トークンの名前と同じかを確かめる
    - グループの文書の `joinCode` は、メンバーも読める（コードを知った子が ほかの子に教えられるのと同じなので、隠さない）。外した人も、コードを知っていれば また入れる。入れたくないときは作り直す
    - ヘッダーは、見本の先生・メニュー・授業時間を出さず、「本番のデータ」と出す。メニューは「きょう」「はてな」「ミッション」「メンバー」。クラスの切り替えから見本のクラスを選ぶと `/teacher` にもどる（本物と架空のデータを1つの画面に混ぜない）

  - 本番の Firestore への反映（2026-11-06）：グループの文書（`jphacks`・`csennkai`・`c3`）・メンバー（ログイン ID `3`・`a` は JPHACKS と C専会の member、`saku_0875` は3つの admin）を作り、`public` の 15 件を消し、この rules を反映した。Vercel（アプリ）はまだ古い版のままなので、本番の「みんなの はてな」は、アプリを公開し直すまで「ひらけなかったよ」になる

## 9 費用と待ち時間（実測）
2026-10-24 に、タイルの床のテスト画像（切り抜き・学年4年生・問い3つ）で、本物の API を1回ずつ測った値。1回の測定なので、ばらつきがある。入力は約6,700トークン（画像とプロンプト）。

| モデル・設定 | 時間 | 出力トークン | 1回あたりの費用 | 問いの質 |
|---|---|---|---|---|
| Haiku 5.5・effort=medium | 28秒 | 4,849 | 約 $0.003 | 答えのヒントが多く、驚きが少ない |
| Haiku 5.5・medium・考える処理オフ（`LLM_THINKING=off`） | 9〜10秒 | 1,166 | 約 $0.001 | ヒントが問題文に入り、驚きがない |
| Sonnet 5.5・effort=low | 13秒 | 1,465 | 約 $0.03 | 写真のタイルを数えた問いが出る。標準的 |
| Sonnet 5.5・effort=medium | 16秒 | 2,409 | 約 $0.04 | 同上 |
| Opus 5.5・effort=medium | 45秒 | 4,691 | 約 $0.12 | 驚きのある問い（点の数の比較など）。いちばん良い |

- 出力トークンには、考える処理の分も含まれる（Opus・Haiku の既定では、これが時間と費用の大半を占める）
- 計算の元の料金は、100万トークンあたり：Haiku 5.5＝$0.10／$0.50、Sonnet 5.5＝$2／$10、Opus 5.5＝$4／$20（入力／出力）
- 1回あたりの時間と費用を測るには、サーバーのログ `[llm]` の `ms`・`inputTokens`・`outputTokens` を見る
- 待ち時間は、いまは認識結果の確認の前に、問いがすべてそろうまで待つ。短くするには、認識結果だけを先に速いモデルで返し、問いは裏で作り続ける案がある（未実装）
- モデルは環境変数 `LLM_MODEL`（`claude-opus-5-5`・`claude-sonnet-5-5`・`claude-haiku-5-5`）、考える深さは `LLM_EFFORT`、考える処理のオフは `LLM_THINKING=off`（Haiku だけ）で変える
- 利用が多いときは API が 429（混雑）を返す。画面には「すこし まってから もういちど ためしてね」と出す（自動で再試行はしない）
- グループの共有を広げるときは、モデレーション API（`docs/01-overview.md` 11章）が必要（いまは、メンバーの通報と、管理者が `/teacher/groups` から消す形。通報された投稿を自動で隠す・通報の乱用への対策は、広げるときに決める）
