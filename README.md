# かこってはてな!?

[![IMAGE ALT TEXT HERE](https://jphacks.com/wp-content/uploads/2026/07/IMG_5316.png)](https://www.youtube.com/watch?v=piaNsc6ilBI)

## 製品概要
### 背景(製品開発のきっかけ、課題等）
いまは、わからないことを AI に聞けば、すぐに答えが返ってきます。とても便利な一方で、子どもが「自分で問いを立てて、考える」前に答えを受け取る場面が増えています。理系（算数・理科・情報）への興味の入口は、答えを知ることよりも、「なんでだろう？」と自分で気づくことにあると、私たちは考えました。

身のまわりには、数や理科のふしぎがたくさんかくれています。信号が1日に青になる回数、ガチャを全種類そろえるまでの平均回数、氷がとけたときのコップの水の高さ、QR コードの白黒の並べ方の数。けれど、子どもが日常の景色の中でそれに気づく機会は多くありません。既存の画像検索・チャット AI・図鑑アプリは「答え」を出してくれますが、「問い」を見つける仕事は、人間の側に残っています。

日本では理系に進む人が少ないと言われています。その原因の一つに、小学生のうちに、理系科目へ興味を持つ機会が少ないことがあると考えました。そこで、AI を「答えを出すため」ではなく「問いを見つけるのを手伝うため」に使い、子どもが自分で「はてな」をつかまえる体験を作りました。

また、学校では、特に低学年の授業（生活科など）で、「身のまわりから気になることを自分で探す」ことが大切にされています。そのきっかけ作りにも使えると考えています。

### 製品説明（具体的な製品の説明）
**かこってはてな!?**は、日常の風景から理系の「はてな（問い）」を見つける、小学生向けのアプリです。名前は、「かこって（囲んで）」気になる所を指定すると、そこにかくれた「はてな!?」が出てくる、という体験から付けました。

- デモ：https://fk2601.vercel.app （「はじめて」でログイン ID とパスワードを決めると使えます。カメラが使えない場合は、ホームの「見本の絵」からも、最後まで試せます）
- 現在は **Web アプリ**です。アプリをインストールしなくても、スマートフォンのブラウザで URL を開けば使えます。今後は、**モバイルアプリとして動かすことも検討**しています。

体験の流れは次のとおりです（その場の体験は1〜3分で終わるように作っています）。

1. **撮る**：カメラで撮影するか、アルバムから写真を選びます。
2. **囲む**：写真の気になる部分を、指でぐるっと囲みます（自由な投げ縄）。囲まないと問いは出ません。
3. **はてなを選ぶ**：囲んだ部分から、AI が「予想がはずれて、おどろく」問いを3つ作ります。3つから選ぶこともでき、自分で問いを書くこともできます。
4. **せーの！（予想）**：答えを見せる前に、子ども自身が予想します。学年に合わせて、4年生までは5つの範囲から選び、5年生からはスライダーや数の入力で答えます。
5. **こたえあわせ**：答えと予想のズレを、数直線・倍率（「予想の約7倍！」）・身近なものへの言いかえで見せます。ズレの大きさで「ピタリ（誤差5%以内）／おしい（2倍以内）／大はずれ」を判定し、ナビ（キャラクター）の表情とはんこが変わります。
6. **なぞとき（解説）**：ナビが、答えまでの考えかたを手順で説明します。もとにした数や出典も見られます。
7. **もしも**：条件（数・大きさなど）をスライダーで変えて、答えがどう変わるかを、その場で確かめられます。
8. **ずかんに のこす**：写真（切り抜き）・問い・予想・結果を「はてなずかん」に保存します。分類（さんすう・りか・じょうほう）ごとにスタンプが集まり、集めると称号がもらえます。「みんなにも みせる」を選ぶと、切り抜き画像・問い・称号を、名前を出さずに公開できます。

### 特長
#### 1. 問いを見つけるのは子ども自身。予想がはずれるおどろきが、学ぶきっかけになる
写真を自分で「囲む」操作をしないと、問いは出ません。どこに注目するかを子どもが決めるので、受け身の学びになりにくい作りです。

さらに、答えを見せる前に予想してもらう流れにしています。AI には、「多くの子どもの予想が正解から5倍以上ずれる問い」や「思いこみがひっくり返る問い」を作るよう指示し、数えるだけ・かけ算1回で出る「ただの計算」の問いは避けさせています（例：ガチャ10種類をぜんぶそろえる平均は約29回／氷がとけてもコップの水の高さは変わらない）。

**なぜ、予想がはずれると学びたくなるのか。** 人は、自分の予想と結果がちがったとき、「どうして？」と知りたくなる（好奇心）と言われています（情報のギャップ理論）。また、自信を持っていた答えがまちがっていたと気づいたときのほうが、正しい答えが記憶に残りやすいという研究（ハイパーコレクション効果）もあります。まず予想して、ズレにおどろくことで、その後の「なぞとき」を、自分から読みたくなる状態を作ることをねらっています。

#### 2. 答えは AI に計算させず、コードで計算して確かめる
AI は計算をまちがえることがあり、子どもがまちがった答えを覚えてしまうおそれがあります。そこで AI には「式」と「変数」を出させ、答えはアプリ（math.js）が計算します。AI 自身が考えた答えと、式から計算した答えが5%以上ずれる問いは、出さないようにしています。「もしも」で条件を変えたときの再計算も、同じ式をアプリ側で解くので、AI を呼ばずに一瞬で動きます。

ただし、AI の説明の中の「事実」（出典や、もとにした数の説明など）は、まちがっている可能性があります。この課題への対策は、「解決出来ること」と「今後の展望」に書きました。

#### 3. 学年に合わせた言葉づかいと、使った進み具合に合わせた難しさ。子どもが使う前提の安全面
設定で学年を決めると、漢字・ふりがな・単位・予想の入力方法・解説の言葉づかいが、その学年に合わせて変わります（22px 以上の漢字にはふりがな、小さい文字はひらがな、むずかしい言葉はやさしい言葉に言いかえ）。一方、**問いの難しさは、学年ではなく、本人がどれだけアプリを使ったか（進み具合）によって上がっていく**ようにしています。同じ学年でも、進みの早い子・ゆっくりの子で、ちがう難しさの問いが出ます。

安全面では、次の対策をとっています。
- 起動時と撮影時に「人の顔はとらないでね」「まわりに気をつけてね」を表示する
- 顔が映ってしまった写真を囲んだ場合に備えて、AI に「人が主役の写真では問いを作らない」ように指示している
- AI には、不適切なジャンルや、危険な行動をすすめる問い（火・刃物・電気・薬品・高い所・道路など）を出さないよう指示している
- AI に送る画像は、囲んだ部分の切り抜きを使い、外側は白で塗りつぶし、位置情報などの情報を消して縮小している
- 公開する情報は、切り抜き画像・問い・分類・称号とし、ユーザー名と位置情報は含めない設計にしている
- 今後、保護者や学校が子どもの利用状況を見られる仕組みを実装する予定（「今後の展望」に記載）

### 解決出来ること
- 子どもが、身のまわりの景色の中に、算数・理科・情報のふしぎがあることに気づくきっかけになります。「これも数学と結びつくのか！」という発見が、理系への興味の入口になります。
- 答えをもらう前に「予想する」ことで、自分で考える習慣と、直感がはずれたときの「なんで？」という好奇心が育ちます。
- 学校の授業（特に、気になることを自分から探す学習をする低学年）の手伝いになります。教室の外の景色を教材にでき、先生が個別に問いを用意しなくても、子どもごとに問いが出ます。
- 保護者や先生は、端末を貸せば、子どもが一人で使えます。学年と進み具合に合わせた問いが出るので、教える側の準備の負担を小さくできます。散歩・お出かけ・授業・自由研究など、場所を選ばず使えます。

**AI がまちがった情報を広めないために。** 子どもが使うサービスでは、AI の説明がまちがっていた場合の影響が大きいため、対策を考え続ける必要があると考えています。現在は、次の対策をとっています。
- 答えの数値は、AI ではなくコードで計算し、AI の答えと照らして検算する
- 解説に、もとにした数や考えかた（出典・前提）を併記して、子どもや保護者が確かめられるようにする
- 出典のリンクは、AI が実在すると判断できるときに書かせ、自信がないときは書かせない（作り話のリンクを書かせない）。表示するリンクは、https のものにしている

今後は、次の対策を進めます。
- 学校などの学習機関と提携し、**教科書を情報源として確認させる**（AI が出した解説や数が、教科書の内容と合っているか照らし合わせる）
- 先生や保護者が、子どもが見た問いと解説を、あとから確認できるようにする
- 出典のある問いを優先して出す、事実があやしい問いを報告できる、などの仕組みを入れる

### 今後の展望
- **実際に小学生に使ってもらい、意見を聞く**：問いのおもしろさ・難しさ・言葉づかいを、子どもや保護者、先生の声をもとに直します。
- **モバイルアプリ化**：現在の Web アプリに加えて、モバイルアプリとして動かすことを検討しています。
- **学習機関向けの管理ページ**：提供した学校などの教育機関が、子どもたちの利用状況（使った回数・集めたスタンプなど）を見られる管理ページを作ります。保護者が見られる仕組みも合わせて検討します。
- **みんなのはてなの発展**：いまの「みんなの はてな」（名前を出さずに公開する）に加えて、クラスのグループ、仲のよい友達のグループなど、小さなコミュニティを作れるようにし、その中で見つけた問いを共有できるようにします。授業などで、先生がグループを作ってお題を出す機能も予定しています。
- **情報の正しさの対策**：上に書いた、教科書を情報源とする確認や、学習機関との提携を進めます。
- **安全の強化**：画像と生成文のチェック（モデレーション）、送信前に他人の顔を自動でぼかす機能、不適切な投稿を消す手段（通報など）を入れ、匿名公開を安心して広げられるようにします。
- **学習の進み具合の改善**：いまは使った数から難しさを決めていますが、正答の傾向なども使って、一人ひとりに合う難しさにします。
- **はてなマップ**：つかまえた場所を地図で見返せるようにします（位置は自分のずかんで使い、公開には含めません）。
- **使う場面を広げる**：兄弟で1台を使うためのプロフィールの切りかえ、「別のもので試す」（同じ考えかたの別の問いを AI が出す）、授業・自由研究での利用を進めます。

### 注力したこと（こだわり等）
* **「答え」ではなく「問い」を出す体験の設計**：囲む → 予想 → こたえあわせ → なぞとき → もしも という、1〜3分の流れを作り込みました。「予想がはずれるおどろき」が出るよう、AI へのプロンプトを、実際の AI で何度も試して書き直しました（数えるだけの問いや、答えが問題文に書いてある問いを避ける指示と、よい例・悪い例を入れています）。
* **答えの正しさ**：AI に計算させず、式をコードで計算して検算する仕組みにしました。確率・場合の数（ガチャの平均回数・誕生日の確率など）の式も、安全に計算できるようにしています。
* **小学生が読めること**：ふりがなの記法を決め、大きい文字にはふりがな、小さい文字はひらがなに自動で直します。熟語を1字ずつ読んで「前提」が「まえてい」になるような読みを防ぐため、AI に熟語ごとにふりがなをつけさせ、むずかしい言葉をやさしい言葉に言いかえさせています。
* **変化が目で見えること**：答えの数がふえる動き、予想の位置から答えの位置へ旗が動く数直線、条件を変えたときの「もとの約○倍」と「さっき／いま」のぼうグラフなど、ズレと変化が一目でわかるようにしました。見た目は、デザイン見本（色・形・ナビの7つの表情）を決めて、全画面でそろえています。
* **動作の確かさ**：本物の Claude・Firebase で、撮影から保存までを通して確かめました。AI が使えないときや、会場で撮影できないときでも、見本の絵（ガチャ・信号・氷のコップ）で最後まで体験できます（AI を呼ばずに、見本の問いに切りかわります）。本番環境でログインの確認が動かなくなる不具合も、ログのエラーから原因を特定し、ライブラリを使わない確認に作り直して解決しました。
* **コストと速さの検討**：Opus・Sonnet・Haiku を同じ写真で比べて、待ち時間と費用を実測しました（Sonnet 5.5・考える深さ low で、約13〜20秒、1回およそ3セント）。待ち時間は、ナビの「まめちしき」でつなぎます。
* **AI の情報の正しさへの向き合い**：計算をコードに任せる、出典・前提を併記する、作り話のリンクを書かせない、という対策を入れたうえで、今後の課題（教科書での確認・学習機関との提携）を整理しました。

## 開発技術
### 活用した技術
#### API・データ
* Claude API（Anthropic Messages API。画像入力と、Zod で定義した形の構造化出力（JSON）。本番は Claude Sonnet 5.5、環境変数で Opus 5.5・Haiku 5.5 にも切りかえ可能）
* Firebase Authentication（ユーザー名とパスワードでのログイン。ユーザー名を英数字に変換してメール形式で登録するので、メールアドレスは集めません）
* Cloud Firestore（プロフィール・はてなずかん・匿名公開の保存。セキュリティルールで、本人のデータは本人しか読み書きできないようにしています。匿名公開の分は、投稿した本人が消せます）
* Google の ID トークン用の公開鍵（securetoken の X.509 証明書）：ログインしていない人が AI を呼べないよう、サーバー側でトークンを確認するために使用
* Google Fonts（Mochiy Pop One・Zen Maru Gothic。`next/font` で配信）
* ブラウザの標準 API（getUserMedia によるカメラ、Pointer Events と Canvas による投げ縄と切り抜き）

#### フレームワーク・ライブラリ・モジュール
* Next.js 16（App Router）・React 19・TypeScript 5.9
* Tailwind CSS 4（デザイン見本の色・影・角丸を、テーマとして定義）
* math.js 15（AI が出した式を、eval を使わずに安全に計算。使える名前を限定し、危険な関数は無効化）
* Zod 4（AI の出力の形の定義と検証）
* @anthropic-ai/sdk、Firebase JavaScript SDK 13
* Vercel（公開。関数は東京リージョン）

#### デバイス
* スマートフォン（iOS Safari・Android Chrome の最新版）：カメラでの撮影、指での投げ縄の操作。現在は Web アプリで、今後、モバイルアプリ化を検討しています
* パソコンのブラウザでも動作します（カメラが使えない場合は、アルバムの写真か、見本の絵で試せます）
